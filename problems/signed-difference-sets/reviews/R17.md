### F3 Name clash: RealCharsRows and MarkedCountsCheck cannot be imported together (root build will fail)

Exact input: a file with `import SignedDifferenceSets.RealCharsRows` then `import SignedDifferenceSets.MarkedCountsRows.Part01`
(`R17/Axioms2.lean`, first version) fails:
`error: import SignedDifferenceSets.MarkedCountsCheck failed, environment already contains
'SignedDifferenceSets.instDecidableKills_1' from SignedDifferenceSets.RealCharsRows`.
Cause: anonymous instances get auto-names; `SelfConjugacyCheck.lean:61` takes `instDecidableKills`, so both
`RealCharsRows.lean:40` (`Decidable (RcCert.Kills …)`) and `MarkedCountsCheck.lean:77` (`Decidable (McCert.Kills …)`) become
`instDecidableKills_1`, and so would the untracked `GaussCharsRows.lean:30`. Each module builds alone, so per-module
`lake build` never saw it; the planned "add the modules to the root, root build" will fail, and by CLAUDE.md (Lean) the
rows count only once a root imports them. Not a soundness problem. Fix: name the instances (e.g.
`instance RcCert.instDecidableKills …`, `McCert.instDecidableKills`, `GcCert.instDecidableKills`), rebuild the affected
modules and their row parts, then build the root. Check other new modules for the same pattern before the root build.
