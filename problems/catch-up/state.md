  - Plain reading: take the 2p consecutive numbers a, a+1, …, a+2p−1 with a ≥ 6p − 2. The player to move has score s, the opponent s + (p mod 2): level when p is even, one point ahead when p is odd. With perfect play on both sides the game ends level. For p even this is Catch-Up itself on the block, player 1 opening (`value_block_draw`: `value (Icc a (a + 2p − 1)) = draw`). For p odd the block's total is odd, so Catch-Up on the block alone is a player-1 win; the statement is about the position one point behind, as inside a larger game.
  - Traps: ℕ subtraction in 2p − 1 and 3(2p − 1) is exact since p ≥ 1; `p % 2` is 0 or 1; `addLeftEmbedding a` is x ↦ a + x, so the set is `Icc a (a + 2p − 1)` (`map_range_eq_Icc`); only the score difference matters (refuter, from the definition and numerically); `false` (not the opening) restricts nothing: at a deficit of 0 or 1 every pick catches up, so the turn is one pick like the opening (`valueAux_true_eq_false`); p = 0 would hold trivially.
